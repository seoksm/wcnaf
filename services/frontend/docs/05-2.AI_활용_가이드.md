## 개요

이 문서는 프론트엔드 개발 과정에서 AI Agent를 활용하여 UI 화면을 구성하고, 코드 생성 및 수정 요청을 효과적으로 진행하기 위한 가이드입니다.

AI Agent를 사용할 때는 단순히 “화면을 만들어줘”라고 요청하기보다 다음 정보를 함께 제공해야 합니다.

- 프로젝트 개발 규칙
- 화면 요구사항
- UI Builder에서 생성한 컴포넌트 리스트
- API 정보
- 상태 처리 방식
- 완료 기준

---

### 전체 작업 흐름

1. UI Builder에서 화면 구성
2. 구성된 컴포넌트 리스트 복사
3. AI Agent에 프로젝트 규칙 파일 추가
4. 요구사항, 컴포넌트 리스트, API 정보를 포함해 프롬프트 작성
5. Agent 실행
6. 결과 확인 및 검토
7. 필요한 경우 수정 요청 또는 직접 수정 진행

# 1. UI 구성

## 1.1 UI Builder 경로로 이동

먼저 공통모듈을 실행 시키고 다음 경로로 이동합니다.

```text
/ui-builder
```

![screen4](<images/screen4.png>)

UI Builder는 화면을 시각적으로 구성하기 위한 도구입니다.

직접 코드를 작성하기 전에 UI Builder를 통해 다음 항목을 정리합니다.

- 화면에 필요한 컴포넌트
- 컴포넌트 배치 순서
- 화면의 전체 레이아웃
- 사용자 입력 영역
- 데이터 표시 영역
- 주요 액션 버튼
- 모달, 테이블, 페이지네이션 등 부가 요소

---

## 1.2 컴포넌트 팔레트에서 UI 구성

컴포넌트 팔레트에서 필요한 컴포넌트를 선택하여 화면을 구성합니다.

![screen5](<images/screen5.png>)

제공되는 컴포넌트는 다음과 같습니다.

| 분류 | 항목 |
|---|---|
| 레이아웃/구조 | WiniBox, WiniGridLayout, WiniTab, WiniTreeView, WiniAccordion, WiniDialog |
| 입력폼 | WiniText, WiniSelect, WiniRadio, WiniCheckbox, WiniInputLabel, WiniSwitch, WiniDateTimePicker |
| 액션/버튼 | WiniButton, WiniButtonGroup, WiniIconButton, WiniToggleButton |
| 기타 | WiniAgGridReact, WiniPagination, WiniValue, WiniIcon, WiniTypography, WiniCodeEditor |

## 1.3 레이아웃 생성 및 컴포넌트 리스트 복사

UI 구성이 완료되면 우측 상단의 '레이아웃 생성' 버튼을 눌러 컴포넌트 리스트를 생성합니다.

![screen6](<images/screen6.png>)

생성이 완료되었으면 하단에 '컴포넌트 리스트'를 복사합니다.

![screen7](<images/screen7.png>)

복사한 컴포넌트 리스트는 AI Agent 프롬프트 작성 시 `UI 구성 정보`에 붙여 넣습니다.

```text
  WiniAgGridReact [x:10, y:10, w:1774, h:518] (속성: )
    그리드 컬럼1 (컬럼명: 구분, 컬럼 값 예시: 이용자, 컬럼 속성: )
    그리드 컬럼2 (컬럼명: 조회 대상자명, 컬럼 값 예시: 형*리, 컬럼 속성: )
    그리드 컬럼3 (컬럼명: 접근일시, 컬럼 값 예시: 2026-01-30 09:14:09, 컬럼 속성: )
    그리드 컬럼4 (컬럼명: 접근이력, 컬럼 값 예시: 사용자 생성, 컬럼 속성: )

```

# 2. AI Agent 프롬프트 작성

AI Agent에게 작업을 요청하기 전에 프로젝트 규칙과 화면 요구사항을 명확히 전달해야 합니다.

## 2.1 프로젝트 규칙 파일 추가

AI Agent를 실행하기 전에 반드시 다음 파일을 컨텍스트에 추가합니다.

```text
docs/AI_RULES_MASTER.md
```

![screen8](<images/screen8.png>)

이 파일은 다음과 같은 프로젝트의 공통 개발 규칙을 정의합니다.

- 폴더 구조
- 파일 네이밍 규칙
- 컴포넌트 작성 방식
- API 호출 방식
- 상태 관리 방식
- 타입 정의 방식
- 공통 컴포넌트 사용 규칙
- 금지된 패턴
- lint, format 규칙

AI Agent는 이 파일을 기준으로 코드를 생성해야 하므로, 프롬프트 상단에 다음 문장을 반드시 포함합니다.

```text
docs/AI_RULES_MASTER.md 파일을 먼저 확인하고, 해당 규칙을 반드시 준수해서 작업해 주세요.
```

---

## 2.2 프롬프트에 포함해야 할 정보

AI Agent 프롬프트에는 다음 정보를 포함하는 것이 좋습니다.

| 항목 | 필수 여부 | 설명 |
|---|---:|---|
| 작업 목표 | 필수 | 어떤 화면 또는 기능을 구현할 것인지 설명 |
| 대상 파일 | 권장 | 생성 또는 수정할 파일 경로 |
| UI 구성 정보 | 필수 | UI Builder에서 복사한 컴포넌트 리스트 |
| API 정보 | 선택 | endpoint, method, request, response 구조 |
| 기능 요구사항 | 필수 | 검색, 초기화, 저장, 수정, 삭제, 페이지네이션 등 구체 동작 |
| UI 요구사항 | 권장 | 화면 배치, 컴포넌트 사용 방식, 공통 컴포넌트 우선 사용 여부 |
| 코드 작성 기준 | 권장 | 프로젝트 규칙, 타입 정의, API 분리, 불필요한 변경 금지 등 |
| 완료 기준 | 권장 | 화면 렌더링, 기능 동작, 상태 처리, JavaScript 및 lint 오류 여부 |

---

## 2.3 AI Agent 프롬프트 기본 템플릿

아래 템플릿을 복사해서 사용합니다.
요구사항을 구체적으로 작성할수록 좋습니다.

````text
## 작업 목표
사용자 관리 화면을 구현해 주세요.
사용자는 이름, 이메일, 상태 조건으로 사용자를 검색할 수 있고,
검색 결과를 테이블로 확인할 수 있어야 합니다.

## 대상 파일
생성 또는 수정할 파일 경로는 다음과 같습니다.
- src/pages/user-log
- src/features/user-log

## UI 구성 정보
[여기에 UI Builder에서 복사한 컴포넌트 리스트를 붙여넣기]

## API 정보
### 사용자 목록 조회 API
- method: GET
- endpoint: /api/users

### request query
```json
{
  "name": "string",
  "email": "string",
  "status": "ACTIVE | INACTIVE",
  "page": 1,
  "size": 20
}
```

### response
```json
{
  "items": [
    {
      "id": 1,
      "name": "홍길동",
      "email": "hong@example.com",
      "status": "ACTIVE",
      "createdAt": "2025-01-01T00:00:00Z"
    }
  ],
  "totalCount": 100,
  "page": 1,
  "size": 20
}
```

## 기능 요구사항
- 최초 진입 시 사용자 목록을 조회해 주세요.
- 검색 버튼 클릭 시 입력한 조건으로 목록을 다시 조회해 주세요.
- 초기화 버튼 클릭 시 검색 조건을 비우고 1페이지부터 다시 조회해 주세요.
- 페이지 변경 시 현재 검색 조건을 유지한 상태로 목록을 조회해 주세요.
- 로딩 중에는 테이블 영역에 loading 상태를 표시해 주세요.
- 조회 결과가 없으면 empty 상태를 표시해 주세요.
- API 에러 발생 시 사용자에게 에러 메시지를 표시해 주세요.

## UI 요구사항
- PageHeader 하단에 검색 영역을 배치해 주세요.
- 검색 영역 하단에 테이블을 배치해 주세요.
- 테이블 하단에 Pagination을 배치해 주세요.
- 삭제, 수정 등 위험 액션은 사용자가 명확히 인지할 수 있도록 처리해 주세요.
- 기존 프로젝트에서 사용하는 공통 컴포넌트가 있으면 우선 사용해 주세요.

## 코드 작성 기준
- 기존 프로젝트의 폴더 구조와 네이밍 규칙을 유지하세요.
- 불필요한 임의 라이브러리는 추가하지 마세요.
- 타입을 명확히 정의해 주세요.
- API 호출 로직과 UI 컴포넌트 로직을 적절히 분리해 주세요.
- 중복 코드는 최소화해 주세요.
- 요청한 기능과 관련 없는 파일은 수정하지 말아 주세요.

## 완료 기준
- 화면이 정상적으로 렌더링되어야 합니다.
- 검색, 초기화, 페이지네이션이 동작해야 합니다.
- loading, empty, error 상태가 처리되어야 합니다.
- TypeScript 오류가 없어야 합니다.
- lint 오류가 없어야 합니다.
````

# 3. Agent 요청 후 확인 및 수정

AI Agent가 코드를 생성하거나 수정한 후, 변경된 파일 목록과 변경 내용을 먼저 확인합니다.

---

## 3.1 확인해야 할 항목

| 확인 항목 | 설명 |
|---|---|
| 프로젝트 규칙 준수 | `docs/AI_RULES_MASTER.md` 기준을 따랐는지 확인 |
| 파일 위치 | 올바른 폴더에 파일이 생성되었는지 확인 |
| 컴포넌트 사용 | 기존 공통 컴포넌트를 재사용했는지 확인 |
| API 연동 | endpoint, method, request, response 구조가 맞는지 확인 |
| 상태 처리 | loading, empty, error 상태가 처리되었는지 확인 |
| UI 일치 여부 | UI Builder에서 구성한 레이아웃과 일치하는지 확인 |
| 불필요한 변경 | 요청하지 않은 파일이나 구조가 변경되지 않았는지 확인 |
| 라이브러리 추가 여부 | 불필요한 패키지가 추가되지 않았는지 확인 |

---

## 3.2 수정 요청 프롬프트 예시

Agent 결과에 문제가 있는 경우, 문제점을 구체적으로 작성해서 다시 요청합니다.

```text
아래 항목을 수정해 주세요.

1. UserTable 컴포넌트에서 status 값이 ACTIVE, INACTIVE 그대로 노출되고 있습니다.
   화면에는 "활성", "비활성"로 표시되도록 수정해 주세요.

2. 검색 초기화 버튼 클릭 시 검색 조건은 초기화되지만 목록이 다시 조회되지 않습니다.
   초기화 후 page=1 조건으로 목록을 다시 조회하도록 수정해 주세요.

3. API 호출 로직이 컴포넌트 내부에 직접 작성되어 있습니다.
   docs/AI_RULES_MASTER.md 규칙에 맞게 api 파일로 분리해 주세요.

4. 수정 대상 파일 외의 변경은 하지 말아 주세요.
```

수정 요청 시에는 불필요한 전체 재작성이나 대규모 리팩터링을 막기 위해 다음 문구를 함께 사용합니다.

```text
전체를 다시 작성하지 말고, 현재 생성된 코드를 기준으로 필요한 부분만 수정해 주세요.
```

또는 다음과 같이 작성합니다.

```text
기존 구조는 유지하고, 아래 문제만 해결해 주세요.
```
