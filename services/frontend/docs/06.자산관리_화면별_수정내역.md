### 3.2 나의 재물조사 및 모바일 사진 촬영

- 상태: `DONE`
- 우선순위: `P0`
- 대상 파일:
  - `src/features/inventory/scan/model/usePhotoCapture.js`
  - `src/features/inventory/scan/api/api.js`
  - `.env`
  - `vite.config.ts`
  - 운영 환경의 Gateway 또는 Reverse Proxy 설정

#### 확인된 원인

- model 훅에서 `connector.client.post`와 `fetch`를 직접 호출한다.
- presigned URL을 개발 서버의 `/s3-proxy`로 변환한다.
- `/s3-proxy` 구현은 Vite `configureServer` 기반이므로 운영 배포 환경에서 동일하게 제공된다는 보장이 없다.
- 촬영·업로드 시간에 `new Date()`를 사용한다.

#### 적용 내역 — 2026-09-22

1. 업로드 준비 API와 presigned PUT 요청을 `scan/api/api.js`로 분리했다.
2. presigned PUT은 `OpenCommunicator` 기반의 무인증 클라이언트를 사용해 Authorization, 조직, 메뉴 헤더가 추가되지 않도록 했다.
3. 개발 모드는 기존 Vite `/s3-proxy`를 유지하고, 운영 모드는 `VITE_S3_UPLOAD_PROXY_PREFIX`로 Gateway 또는 Reverse Proxy 경로를 주입하도록 분리했다.
4. HTTPS 운영 페이지에서 HTTP presigned URL을 받았는데 운영 proxy가 설정되지 않은 경우, 브라우저의 mixed-content 실패 전에 사용자 안내를 표시한다.
5. 촬영 시각과 업로드 완료 시각을 `winiDate.now().toISOString()`으로 생성한다.
6. ref guard로 사진 업로드의 빠른 중복 실행을 차단하고 `finally`에서 loading 상태를 항상 종료한다.
7. connector를 ref로 참조해 `useCallback` 의존성에서 connector 객체를 제거했다.
8. `PhotoCaptureButton`의 숨겨진 native file input은 모바일 카메라 호출에 필요한 예외이므로 유지했다. 재촬영을 위해 파일 선택 직후 input 값을 초기화하는 기존 동작도 유지했다.

#### 운영 배포 조건

- S3/MinIO가 HTTPS endpoint를 제공하면 `VITE_S3_UPLOAD_PROXY_PREFIX`를 비우고 presigned HTTPS URL을 직접 사용한다.
- presigned URL이 HTTP라면 운영 Gateway 또는 Reverse Proxy에 업로드 스트림을 전달하는 경로를 구성하고, 빌드 환경의 `VITE_S3_UPLOAD_PROXY_PREFIX`에 해당 경로를 지정해야 한다.
- proxy는 presigned URL의 path/query와 대상 Host를 변경하지 않고 전달해야 하며, 요청 body 크기 제한이 실제 모바일 사진 크기보다 충분히 커야 한다.
- 운영 인프라 설정과 실제 배포 환경 확인을 완료했다.

#### 적용 내역 — 2026-09-22 (선택 개선 사항 처리)

- `npx eslint`/`npm run build` 통과. `Promise.allSettled`는 표준 JS API 동작이라 별도 probe 없이 코드 검토로 확인함(프레임워크 특이 동작이 아님).

- 상태: `DONE`
