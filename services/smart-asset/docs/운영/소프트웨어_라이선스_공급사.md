# S-520 소프트웨어 마스터, S-530~533·550 라이선스, S-540 공급사 - 관리자 등록 가이드 및 알려진 제한

## 배경

Step 7(Phase 4-2). Q-46 확정대로 SW 라이선스는 무형자산과 완전히 분리된 별도 애그리게이트다.
라이선스 1건(`license`)은 세 개의 하위 테이블을 가진다 - 구매내역(`license_purchase_record`,
보유수량의 근거), 배정 사용자(`license_assigned_user`, `AssetAssignment`와 동일한 소프트
릴리스 이력 패턴), 포함 SW(`license_included_software`, `software` 마스터를 R2 자동완성으로
참조). 공급사(`vendor`)는 렌탈(Step 7 Phase 4-1)과 라이선스가 공용으로 쓴다.

**보유·배정·잔여 수량은 컬럼이 아니라 매 조회마다 계산하는 파생값이다** - `LicenseServiceImpl`이
구매내역 수량 합계(`purchasedQuantity`)와 유효 배정 건수(`assignedQuantity`)를 각각 집계해
`remainingQuantity = purchasedQuantity - assignedQuantity`를 계산한다. Q-47(잔여 수량이
부족해도 배정을 막지 않고 경고만 한다) 확정대로, 잔여가 음수여도 배정 자체는 거부하지
않고 `overAssigned` 플래그로만 표시한다(목록 화면에서 빨간색 "(초과)" 표기).

`license_assigned_user.license_purchase_record_id`가 null인 배정은 "미연결 배정"이다 - 어느
구매건에서 나온 배정인지 특정되지 않은 경우(예: 이미 있던 라이선스를 시스템 도입 이전부터
쓰고 있었던 경우)로, 화면에 명시적으로 표시한다(`unlinkedPurchase`).

## 구현 범위 - 백엔드·프런트엔드 전부 완료

- **S-520** (`software-management/ui/SoftwareManagementPage`) - AssetCategory와 동일한
  "그리드 + 우측 편집기" 단순 마스터 화면. 페이지네이션 없이 전체 목록을 조회한다(대상
  건수가 적을 것으로 예상).
- **S-540** (`vendor-management/ui/VendorManagementPage`) - S-520과 동일한 구조.
- **S-530/531/532/533** (`license-management/ui/LicenseManagementPage`) - 목록(보유·배정·
  잔여 컬럼 포함)에서 "라이선스 등록" 모달(S-531)과 행 클릭 시 상세 모달로 진입. **상세
  모달 하나 안에 구매내역·배정 사용자·포함 SW 세 구획을 세로로 쌓았다** - 렌탈 S-512와
  동일한 단순화 판단(설계문서가 그리는 별도 탭 구조 대신).
- **S-550** (`my-license/ui/MyLicensePage`) - 임직원 모바일 셀프서비스. 배정된 라이선스
  목록과 "회수 요청" 버튼만 제공한다.

## 알려진 제한

- ~~S-550의 "회수 요청"은 티켓을 만들지 않고 플래그만 세운다~~ **(Phase 5에서 해결)**
  Phase 5(서비스데스크) 완료로 `LicenseFacade.requestRelease`가 이제 실제 RETURN 티켓을
  만든다. `release_requested_yn`/`release_requested_at` 플래그는 그대로 유지하지만(중복
  요청 방지용), 실제 회수 처리는 관리자가 서비스데스크에서 그 티켓을 완료 처리하면 자동으로
  이뤄진다(`TicketServiceImpl.completeAsReturn` → `LicenseService.releaseUser`) - 상세는
  `서비스데스크.md` 참고.
- **구매내역·배정·포함 SW 어디에도 삭제/취소 API를 만들지 않았다** - 포함 SW만 예외로
  삭제가 가능하다(단순 태그 성격). 구매내역은 회계 근거 성격이라 삭제 대신 필요하면 수정
  API(`PATCH /license-purchase-record/{id}`)로 정정한다. 배정은 삭제 대신 "회수"(소프트
  릴리스)만 있다 - `AssetAssignment`/Loan과 동일한 append-only 이력 패턴.
- **포함 SW 추가는 자유 텍스트 입력이다.** `software` 마스터에서 이름으로 자동완성 검색을
  띄우는 대신, `Software.findOrCreateByName()`(R2)이 서버에서 존재 확인 후 없으면 새로
  생성한다 - 프런트는 목록 자동완성 UI 없이 텍스트만 입력받는다. 오탈자로 소프트웨어가
  중복 생성될 수 있는 게 트레이드오프다.
- **라이선스 배정 시 "포함 SW 미리보기"는 만들지 않았다.** 임직원이 이 라이선스로 어떤
  SW를 쓸 수 있는지는 S-533 상세의 "포함 SW" 구획에서만 확인 가능하고, S-550(내
  라이선스) 화면에는 노출하지 않는다.
- **공급사·소프트웨어 삭제는 소프트 삭제(status=DISABLE)다** - 이미 참조 중인 구매내역/
  라이선스가 있어도 막지 않는다(FK 제약은 있지만 status 변경 자체는 항상 허용). 목록
  조회는 `status='ENABLE'`만 필터링하므로 삭제된 항목은 그리드에서 사라지지만 과거
  구매내역의 `vendorName`/포함 SW의 `softwareName` 표시에는 영향이 없다(엔티티 관계로
  직접 조회하기 때문).
- **(수정 완료, 2단계) S-533 상세의 구매내역/배정/포함SW 입력 줄이 순수 텍스트였고,
  레이아웃도 깨져 보였다.** 1차로 구매일 텍스트 입력을 `WiniDatePicker`로만 바꿔도 여전히
  깨졌다 - 진짜 원인은 `ui="column"` 모드의 `WiniText`/`WiniSelect`/`WiniDatePicker`가
  내부 `FormControl`에 항상 `width:100%`를 강제해서, 한 줄에 여러 개를 좁은 고정폭
  `className`으로 나열하면 서로 폭을 다투며 깨진다는 것이었다. 이 앱에서 여러 필드를 한 줄에
  배치하는 표준 방식인 `WiniGridLayout container` + `WiniGridItem size={{ xs: N }}`(합
  12)로 구매내역·배정 사용자·포함 SW 세 줄을 전부 다시 짰다(`LicenseDetailDialog`). mock
  props로 다이얼로그만 격리 렌더링한 스크린샷으로 최종 확인했다. 렌탈의 결제 스케줄
  (귀속월/결제일/예상금액)도 같은 원인·같은 방식으로 고쳤다 - `무형자산_렌탈.md` 참고.

## 확인된 동작 · 발견한 문제

- V23(vendor·software·license·license_purchase_record·license_assigned_user·
  license_included_software 6개 테이블) 마이그레이션 작성 시, 과거 세 차례(V15·V20·V22)
  반복했던 "append-only 성격 테이블에 `update_at` 빼먹기" 실수를 막기 위해 컴파일 전
  `awk` 스크립트로 6개 테이블 모두 `create_at`/`update_at` 존재 여부를 사전 검증했다 -
  이번에는 처음부터 문제 없이 통과.
- **`LicenseAssignedUserResponseDto`에 `licenseName`을 처음에 빠뜨렸다** - S-550(내
  라이선스) 프런트를 만들면서 API가 `licenseId`만 주고 이름을 안 준다는 걸 뒤늦게 발견,
  `LicenseAssignedUserInfo`에 `license.getName()`을 추가해 apiSpec·코드를 함께 고치고
  재생성·재컴파일·재기동으로 검증했다. `LicensePurchaseRecordInfo`의 `vendorName`처럼
  연관 엔티티에서 표시용 이름을 미리 채워 보내는 게 이 프로젝트의 관례임을 재확인.
- 컴파일 성공, `smart-asset` 컨테이너 재기동 후 정상 부팅 확인(Hibernate
  `ddl-auto=validate` 통과 - 6개 신규 테이블 스키마 일치), 기존 테스트 스위트
  (`./gradlew test`) 통과.
- 미등록 상태에서 `GET /vendor`, `GET /software`, `GET /license`, `GET /license/my`
  직접 호출 시 `COMMON_UNAUTHORIZED`(403)로 정상 차단 확인.
- 프런트엔드 `npx eslint`(신규 파일만 대상) 클린, `npm run build` 정상 완료
  (`VendorManagementPage-*.js`, `SoftwareManagementPage-*.js`,
  `LicenseManagementPage-*.js`, `MyLicensePage-*.js` 청크 생성 확인).
