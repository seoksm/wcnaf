# 유형자산 엑셀 업서트(S-213) 서명 키 운영 가이드

## 배경

`ExcelRowSignerImpl`은 엑셀 업서트 preview 결과(각 행)에 HMAC-SHA256 서명을 붙여, commit 시
클라이언트가 그 값을 임의로 바꿔서 보내도 서버가 감지할 수 있게 한다. 이 서명 키는
`winitech.smart-asset.excel-upsert.signing-key` 프로퍼티로 주입되며, 실제 값은
**환경변수 `SMART_ASSET_EXCEL_SIGNING_KEY`** 로만 전달한다 - 어떤 `application*.properties`
파일에도 실제 키 값을 적지 않는다.

과거에는 이 키가 `application.properties`에 평문으로 커밋되어 있었다. **그 키는 git 히스토리에
이미 노출되었으므로 영구히 폐기된 것으로 간주한다** - 이후 어떤 환경에서도 재사용해서는 안 된다
(정확한 옛 값이 필요하면 `git log -p`로 해당 파일의 이력을 확인한다 - 이 문서에는 재노출을 막기
위해 값 자체를 다시 적지 않는다).

## 요구 조건

- 최소 32바이트 이상의 충분히 무작위한 값이어야 한다.
- 값이 없거나 32바이트 미만이면 `ExcelRowSignerImpl` 빈 생성 시점(=애플리케이션 기동 시점)에
  즉시 `IllegalStateException`이 발생해 기동이 중단된다. 모든 환경(로컬/도커/테스트/운영)에
  동일하게 적용되며, 예외 메시지에는 키 값이나 그 일부가 절대 포함되지 않는다(길이 조건 위반
  사실만 알린다).
- 키 값은 어떤 로그(애플리케이션 로그, 테스트 로그 포함)에도 남지 않는다.

## 환경별 주입 방법

### 로컬 (`./gradlew bootRun` 직접 실행)

셸에 환경변수를 설정하고 실행한다.

```bash
export SMART_ASSET_EXCEL_SIGNING_KEY=$(openssl rand -base64 32)
./gradlew bootRun
```

### 테스트 (`./gradlew test`)

운영 키를 재사용하지 않는다. `build.gradle`의 `test { environment "ACTIVE", "local,test" }` 설정에
따라 테스트 실행 시에는 `local` 프로필 위에 `test` 프로필이 추가로 활성화되고,
`src/test/resources/application-test.properties`가 커밋해도 안전한 테스트 전용 더미 키
(`integration-test-only-signing-key-do-not-use-elsewhere`)를 주입한다. 개발자가 별도로 환경변수를
설정할 필요가 없다.

Mockito 기반 순수 단위 테스트(`TangibleAssetExcelFacadeTest`, `ExcelRowSignerImplTest` 등)는 Spring
컨텍스트를 아예 띄우지 않고 `new ExcelRowSignerImpl("...")`을 직접 호출하므로, 각 테스트 파일 안에
그 테스트만을 위한 32바이트 이상의 더미 키 리터럴을 둔다 - 이 값들도 운영 키와 무관하며 서로 다른
테스트끼리도 재사용하지 않는다.

### 도커 (`docker compose up`, `docker/docker-compose.yml`의 `smart-asset` 서비스)

`docker-compose.yml`은 `SMART_ASSET_EXCEL_SIGNING_KEY: ${SMART_ASSET_EXCEL_SIGNING_KEY}`로 호스트
환경변수를 컨테이너에 그대로 전달한다. `docker/.env`(git 미추적 - 커밋되지 않는 로컬 전용 파일)에
아래 줄을 추가한다.

```
SMART_ASSET_EXCEL_SIGNING_KEY=<openssl rand -base64 32 등으로 생성한 32바이트 이상 값>
```

### 운영(prod)

이 저장소에는 아직 smart-asset용 Kubernetes/Secret 매니페스트가 존재하지 않는다(다른 서비스들만
`kustomize/`에 정의되어 있다). 운영 배포가 구성될 때는 다른 서비스들과 같은 패턴 - 즉 `Secret`으로
값을 주입하되, 키 이름은 반드시 `SMART_ASSET_EXCEL_SIGNING_KEY`로 맞춘다. 애플리케이션은 이 값이
없거나 32바이트 미만이면 기동을 즉시 실패시키므로, 운영 배포 파이프라인은 이 Secret이 먼저
존재하는지 확인 후 배포해야 한다.

## 키 교체(rotate) 절차

키를 바꾸면 **그 이전에 발급된 모든 preview 서명이 즉시 전부 무효화된다** - `ExcelRowSignerImpl.verify()`가
새 키로 다시 계산한 서명과 옛 키로 만들어진 서명을 비교하므로 더 이상 일치하지 않기 때문이다. 이미
preview를 마치고 아직 확정(commit)하지 않은 사용자는 키 교체 이후 확정을 시도하면
"요청 데이터가 서버가 발급한 미리보기 결과와 일치하지 않습니다. 다시 미리보기해주세요." 오류를 받고,
**다시 미리보기(preview)부터 진행해야 한다.** 이는 의도된 동작이며 버그가 아니다 - 키 교체 공지 시
사용자에게 함께 안내한다.

키를 코드/설정 파일에서 지우는 것만으로는 끝나지 않는다 - 이미 노출된 키는 실제 배포 환경의
비밀 저장소에서도 새 값으로 반드시 교체해야 한다.

1. 새 키를 생성한다: `openssl rand -base64 32` (또는 동등한 CSPRNG 기반 방법).
2. 실제 배포된 비밀 저장소를 갱신한다.
   - 로컬 개발: 각 개발자가 자신의 `docker/.env`(또는 셸 환경변수)를 새 값으로 갱신한다.
   - 운영(향후 Secret이 구성된 이후): 운영 Secret 저장소(K8s Secret 등)의
     `SMART_ASSET_EXCEL_SIGNING_KEY` 값을 새 값으로 갱신한다. **주의: 옛 키를 삭제만 하면 안 되고
     반드시 새 무작위 값으로 교체해야 한다** - 옛 키는 git 히스토리 등으로 이미 노출됐을 수 있어
     재사용이 금지된다.
3. smart-asset 인스턴스를 재시작해 새 키를 반영한다(여러 인스턴스가 있다면 롤링 재시작 중
   신·구 인스턴스가 잠시 다른 키로 동시에 떠 있을 수 있음을 인지한다 - 이 짧은 기간에는 어느
   인스턴스가 요청을 받느냐에 따라 검증 결과가 달라질 수 있으므로, 트래픽이 적은 시간대에
   진행하거나 배포 도구의 표준 롤링 절차를 따른다).
4. 사용자 공지: "엑셀 업서트 미리보기 결과가 초기화되었습니다. 확정 전이라면 다시 미리보기해주세요."
5. 옛 키가 노출된 경위(예: git 커밋)를 파악했다면, 필요시 해당 커밋 이력에 대한 별도 조치(예:
   히스토리 정리)는 이 문서의 범위를 벗어나므로 보안 담당자와 별도로 협의한다.

## 검증

과거에 노출됐던 정확한 키 값은 이 문서에 다시 적지 않는다(재노출 방지) - 필요하면
`git log -p -- services/smart-asset/src/main/resources/application.properties`로 확인한다.
저장소 전체에서 그 값이 더 이상 나타나지 않는지 확인하려면, 위 명령으로 찾은 값을 직접 아래
자리에 넣어 실행한다.

```bash
grep -r "<git log -p로 확인한 옛 키 값>" . 2>/dev/null
```

결과가 없어야 정상이다. 또한 `winitech.smart-asset.excel-upsert.signing-key=` 뒤에 실제 값이
직접 적힌 곳이 없는지도 함께 확인한다(모든 `application*.properties`는 `${SMART_ASSET_EXCEL_SIGNING_KEY:...}`
형태의 환경변수 참조만 가지고 있어야 하며, `src/test/resources/application-test.properties`의
테스트 전용 더미 값만 예외다).
