# S-400 프로세스 설정 - 관리자 등록 가이드 및 알려진 제한

## 배경

Step 6(Phase 3)의 첫 화면. 대여/수령·반납 프로세스 On-Off와 부속 정책(Q-38~45)을 관리하는
싱글턴 설정 화면이다. `process_config` 테이블은 워크스페이스당 단 1행만 존재하며
(`V17__process_config.sql`이 고정 UUID `00000000-0000-0000-0000-000000000001`로 시드),
생성·삭제 API 없이 조회(GET)·수정(PATCH)만 제공한다.

C1(설계문서 §1 - "전 화면이 매 요청 참조하는 전역 상태라 DB 조회로 두면 안 된다") 반영을 위해
`ProcessConfigServiceImpl.loadConfig()`를 Spring Cache(`@Cacheable("processConfig")`)로 캐시하고,
`updateConfig()`에서 `@CacheEvict`로 즉시 무효화한다. `SmartAssetApplication`에 `@EnableCaching`을
추가했고, 별도 캐시 라이브러리 없이 Spring Boot 기본 `ConcurrentMapCacheManager`를 사용한다
(단일 인스턴스 배포 전제 - 인스턴스가 여러 대가 되면 분산 캐시로 교체 필요).

## 알려진 제한 - C2(진행 중 건수 표시·끄기 차단) 미구현

설계문서 §2는 "각 프로세스 헤더에 진행 중 건수를 표시하고, 진행 중 건이 있으면 끄기를
차단한다(C2)"고 명시하지만, 이번 구현 시점에는 `loan`/`acknowledgement` 테이블이 아직 없어
집계할 대상 자체가 없다. 따라서 이번 S-400 화면은 **토글+부속 정책 조회·수정만 제공하고,
끄기 차단·진행 건수 표시는 넣지 않았다** (프론트에 "0건"처럼 가짜 값을 보여주는 대신 아예 빼는
쪽을 택함). S-410(대여 관리)·S-430(확인서 관리) 백엔드를 구현할 때 아래를 함께 추가해야 한다.

- `loanEnabled`를 끄려는 요청 시 `loan` 테이블에서 `returned_at IS NULL` 건수를 세어 0건이
  아니면 거부 (몇 건인지 메시지에 포함)
- `acknowledgementEnabled`를 끄려는 요청 시 `acknowledgement`에서 완료되지 않은 건수를 세어
  동일하게 처리
- `ProcessConfigResponseDto`에 `loanInProgressCount`/`acknowledgementInProgressCount` 같은
  필드를 추가해 프론트 헤더에 표시

## 관리자 등록 절차 (메뉴관리)

다른 신규 화면과 동일하게 마이그레이션/코드 배포만으로는 접근이 열리지 않는다. 아래 4단계를
관리자 UI에서 직접 수행해야 한다 (`불용자산_처분처리.md` §프런트엔드 절차와 동일한 방식).

1. **프로그램 등록** (메뉴관리 → 프로그램 관리)
   - 프로그램명: `프로세스 설정`
   - 프로그램 코드: `SMARTASSET_PROCESS_CONFIG`
   - 프로그램 매핑: `process-config-settings/ui/ProcessConfigSettingsPage`
   - 상태: 사용, 메뉴상태: 사용, 모바일상태: 미사용
2. **메뉴에 매핑** (메뉴관리 → "자산관리" 그룹 → "메뉴-프로그램 매핑" 기능으로, 반드시 이 기능을
   사용 - 일반 "메뉴 추가"로 만들면 `menu_type`이 `MENU`(폴더)가 되어 버그가 난다)
   - 메뉴명: `프로세스 설정`, "자산관리" 그룹의 형제 메뉴로 추가 (기존 화면들처럼 하위 그룹 없이
     평평하게)
3. **메뉴 접근권한 부여** (메뉴 접근권한 화면) - ADMIN에 새 메뉴 체크 후 저장. 저장은 전체 트리
   diff이므로 먼저 새로고침한 뒤 새 체크박스만 추가할 것 (기존 권한을 지우지 않도록)
4. **API 액션 등록** (메뉴관리 → 해당 프로그램 → 액션 등록) - 아래 2건을 정확한 URI로 등록

   | HTTP | URI | authType |
   |---|---|---|
   | GET | `/api/v1/smart-asset/process-config` | SELECT |
   | PATCH | `/api/v1/smart-asset/process-config` | UPDATE |

5. 재로그인 후 메뉴에서 "프로세스 설정" 클릭해 정상 노출·저장을 확인한다.

## 확인된 동작

- V17 마이그레이션 적용 및 시드 행 생성 확인 (`docker exec wcnf-postgres psql -d smart-asset`)
- `smart-asset` 컨테이너 재기동 후 정상 부팅 확인 (`Started SmartAssetApplication`)
- 미등록 상태에서 직접 호출 시 `COMMON_UNAUTHORIZED`(403)로 정상 차단되는 것 확인 - 등록 전까지는
  의도된 동작
- 프런트엔드 `npm run build` 정상 완료 (신규 청크 `ProcessConfigForm-*.js` 생성 확인)
