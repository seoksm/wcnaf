## 2. 확정된 공통 규약 (Step 1)

### 레이아웃 원칙 7개
| 키 | 내용 |
|---|---|
| R1 | 관리자(`/admin/*`)와 임직원(`/my/*`) 셸을 진입점부터 분리 |
| R2 | 관리자는 데스크톱 우선, 임직원은 모바일 우선 |
| R3 | 모든 화면은 패턴 6종 중 하나에 속한다 (신규 패턴 금지) |
| R4 | 목록은 항상 4단 구조 — 헤더 → 필터 → 액션바 → 테이블 → 페이징 |
| R5 | 저장은 항상 오른쪽 아래, 취소는 그 왼쪽 |
| R6 | 파괴적 동작은 목록에서 실행하지 않음 (상세에서만) |
| R7 | 빈 상태를 화면마다 별도 설계 |

### 반복 패턴 6종
`P-1` 목록 · `P-2` 상세(탭형) · `P-3` 등록/수정 폼 · `P-4` 트리+상세 2분할 · `P-5` 엑셀 마법사 4단계 · `P-6` 모달(필드 6개 이하)

### 셸
`L-ADM` 관리자 셸 (GNB 56 + LNB 240, 6개 메뉴그룹) · `L-EMP` 임직원 셸 (상단바 48 + 하단 4탭, 프로세스 설정에 따라 탭 가변)

### 그리드
XL ≥1440 / L 1280–1439 / M 768–1279 / S <768. 간격 값은 4·8·12·16·24만 사용.

## 3. 알림·파일 규약 (Step 2)

### 알림 발송 규약
| 키 | 내용 |
|---|---|
| N1 | 알림은 트랜잭션 밖에서 비동기 발송 — 발송 실패가 업무 롤백을 유발하지 않음 |
| N2 | 발송 대상 0명이어도 그 사실을 이력에 기록 |
| N3 | 재시도 3회 (1·5·30분), 3회 실패 시 관리자 채널에 요약 |
| N4 | 동일 이벤트·수신자 5분 내 중복 발송 차단 |
| N5 | 어댑터는 인터페이스, 초기 구현은 로그 전용 |

**알림 유형 16종** — 즉시 11종 / 배치 5종. (Step 4에서 검토했던 `DEPRECIATION_BATCH_FAILED`는 Q-21 이벤트 기반 결정으로 불필요해져 제외)

### 파일 규약
| 키 | 내용 |
|---|---|
| F1 | 물리 경로 날짜 분산 `/upload/YYYY/MM/DD/{uuid}.ext` |
| F2 | DB에는 경로만, BLOB 금지 |
| F3 | 소프트 삭제 후 30일 뒤 물리 삭제 |
| F4 | 다운로드는 서버 경유 권한 확인 (`/files/{id}`) |
| F5 | 용량 추이를 설정 화면에서 확인 가능하게 |

**파일 컴포넌트 4종** — `C-200` 이미지 그리드 · `C-201` 모바일 촬영 · `C-202` 단일 파일 · `C-203` 뷰어

## 8. 감가상각 계산 규칙 (Step 4 확정 · Q-21 반영)

**이벤트 기반 산출 · 총액법 · 누적 분기** — 스케줄 배치를 두지 않는다.

| 키 | 규칙 |
|---|---|
| D1 | **이벤트 기반 산출** — 자산 등록·취득가액 변경·불용·처분 시 갱신, 결산 자료는 산출 요청 시점 계산. 스케줄 배치 없음 |
| D2 | **산출 단위는 회계연도 누적 분기** — `1~3월` / `1~6월` / `1~9월` / `1~12월`. 월별 자료 없음 |
| D3 | **총액법 표시** — 취득가액 · 감가상각누계액 · 장부가를 항상 함께. 목록은 기초누계 → 당기상각 → 기말누계 → 장부가 순 |
| D4 | 상각 대상은 `life_status` 기준. **불용 처리한 달까지 상각 후 다음 달부터 중단** |
| D5 | 취득가액 0/미입력은 상각 제외 + "기준 미비" 표시 |
| D6 | 종류별 기준 미설정 자산은 별도 집계해 경고 노출 |
| D7 | **확정 액션** — 결산 자료를 넘기는 시점에 사람이 [확정]을 누르면 산출 결과 고정. 미확정 기간은 언제나 실시간 산출 |

- **기산 시점**: 취득월 포함 (법인세법 월할과 일치)
- **비망가액**: 1,000원 — 상각 완료 후에도 대장에서 사라지지 않게
- **회계기준**: K-GAAP 단일
- **재현성**: 배치가 없으므로 미확정 기간은 조회 시마다 재계산될 수 있음 → 확정 액션이 유일한 고정 장치. 산출 기준 시각을 화면에 항상 표기

## 9. 도입 시나리오 — 초기 자산 생성은 엑셀 업로드

기존 자산대장이 없으므로 초기 데이터를 **엑셀 양식 다운로드 → 작성 → 업서트 업로드**로 생성한다.
전수조사는 초기 구축 도구가 아니라 **본래의 정기 실사 기능**으로 설계한다.

| 단계 | 방법 |
|---|---|
| 1 | 관리자가 조직도·멤버·자산 종류·위치를 먼저 세팅 (Step 1~3 화면) |
| 2 | **S-213에서 등록 양식(xlsx) 다운로드** — 양식은 그 시점 마스터 데이터를 반영해 동적 생성 |
| 3 | 엑셀에 보유 자산 작성 (자산코드는 비워둠 = 신규) |
| 4 | **업로드 → 검증 → 확정** (P-5 마법사 4단계, 부분 성공 금지) |
| 5 | QR 자동 생성 → S-216에서 라벨 일괄 발행·부착 |
| 6 | 이후 정기 전수조사로 실물 확인 및 최신성 유지 |

### 양식 파일 규격 (v1 제작 완료)

시트 3개 구조 — 실물 파일은 `유형자산_등록양식_v1.xlsx`

| 시트 | 내용 |
|---|---|
| **작성안내** | 업로드 절차 4단계 · 컬럼 구분 범례 · 필수 규칙 10항 · 감가상각 안내 |
| **자산등록** | 2행 헤더 / 3행 항목설명 / 4~5행 예시 / 6행부터 입력. 15컬럼, 드롭다운·금액 검증 적용 |
| **참조코드** | 자산종류·설치위치·생애상태·배정형태 목록 + 상태 유효조합 매트릭스 |

**15컬럼 구성**
- 필수 5 — 자산명 · 자산종류 · 설치위치 · 취득일 · 취득가액
- 선택 10 — 자산코드(비움=신규) · 모델명 · 제조사 · 시리얼번호 · 생애상태 · 배정형태 · 사용자사번 · 사용자명 · 공급사 · 메모

> 사용자정의 필드 컬럼은 Q-13 재확정(2026-09-16)으로 제외됨 — 추가 항목이 필요해지면 정식 컬럼으로 스키마를 변경하고 이 양식도 그때 다시 설계한다.

**양식 설계 원칙**
| 키 | 규칙 |
|---|---|
| T1 | 양식은 **정적 파일이 아니라 동적 생성** — 자산종류·위치 마스터가 바뀌면 양식도 바뀐다 |

|---|---|
| I1 | 대상 자산은 **시작 시점 스냅샷으로 고정** — 조사 중 자산 변동과 무관 |
| I2 | 동일 임직원은 진행 중 조사 하나에만 참여. 진행 중 조사 간 대상 중복 금지 |
| I3 | 확인은 **QR 스캔으로만 인정** (라벨 훼손 예외는 승인 강제) |
| I4 | **'이상'은 별도 상태** — 파손·위치불일치·타인보유를 '확인'에 섞지 않음 |
| I5 | 반려 시 미확인으로 복귀 + 재검수 알림 |
| I6 | 조사 종료 후 상태 변경 불가 (append-only) |

**핵심 설계 — 미확인 자산 종결 관문(S-308)**

실사는 100%로 끝나지 않는다(휴직자·출장자·라벨 훼손·창고 깊숙한 자산). 자동 분실 처리는 위험하고 방치하면 실사가 무의미하다. 해법은 **판단을 자동화하지 않고, 판단하지 않고 넘어갈 수 없게 만드는 것**:

- 조사 종료 시 미확인 자산 전건에 대해 **차기 이월 / 소재 확인 / 분실 처리** 중 하나를 지정해야 종료 확정 버튼이 활성화됨
- 분실 처리는 불용(사유:분실) 전환 → **장부가를 목록에 노출**해 처분손실 인지시킴
- 분실 처리는 **일괄 지정에서 제외**(R6)
- 2회 연속 이월 시 경고 — 영원히 이월되는 자산 방지

## 11. 프로세스 On/Off 파급 규약 (Step 6 확정)

프로세스 설정 하나가 관리자 메뉴·임직원 탭·자산 상태 선택지·알림 유형을 동시에 바꾼다. **이 매트릭스가 화면 렌더링 조건의 유일한 기준**이다.

| 영향 지점 | 대여 OFF | 대여 ON |
|---|---|---|
| 관리자 LNB | 대여 현황 숨김 | 대여 현황 노출 |
| 임직원 탭 | 3탭 (홈·내자산·문의) | 4탭 (+대여) |
| `assign_type` 선택지 | 미배정·개인배정·공용 | +대여가능·대여중 |
| QR 스캔 액션 | 조회·수리요청 | +대여/반납 |
| 알림 유형 | 반납 연체 제외 | 반납 연체 포함 |

| 영향 지점 | 수령·반납 OFF | 수령·반납 ON |
|---|---|---|
| 관리자 LNB | 확인서 현황 숨김 | 확인서 현황 노출 |
| 임직원 홈 카드 | 승인 대기 없음 | 승인 대기 카드 |
| 자산 상세 액션 | — | 확인서 요청·확인서 탭 |
| 미승인 조회 차단 | 없음 | 적용 |

| 키 | 규칙 |
|---|---|
| C1 | 프로세스 설정은 캐시 + 변경 시 즉시 무효화 |
| C2 | 진행 중 건이 있으면 **끄기 차단** (건수 표시) |
| C3 | 끈 프로세스의 **과거 이력은 계속 조회 가능** |
| C4 | 임직원 탭바는 개수에 따라 균등 분할 (고정 4분할 금지) |

### 대여 규약
| 키 | 규칙 |
|---|---|
| L1 | 대여 처리는 **낙관적 잠금** (`WHERE assign_type='대여가능'` 영향행 0 → 이미 대여됨) |
| L2 | **연체는 상태가 아니라 파생값** — `due_date < 오늘 AND returned_at IS NULL` |
| L3 | 반납 시 자산 상태 확인 강제. 이상이면 수리중 전환 + 티켓 생성 제안 |
| L4 | 연체 중 신규 대여 차단 시 **무엇을 반납해야 하는지** 함께 표시 |
| L5 | 대여 이력은 자산 불용 후에도 보존 |

### 승인 규약 (전자서명 대체)
| 키 | 규칙 |
|---|---|
| K1 | **요청 시점 문서 본문 전문을 스냅샷** 저장 (템플릿 ID만 저장 금지) |
| K2 | 증빙 4종 — 승인자ID · 승인일시 · 접속IP · 자산 스냅샷 |
| K3 | append-only. 취소는 무효화 레코드 추가로 처리 |
| K4 | **2단계 확인** — 체크박스 동의 + 승인 버튼 |
| K5 | 반납은 담당자 승인까지 완료 시 최종 처리 |
| K6 | 미승인 자산은 임직원 조회 차단 (승인 강제 장치) |
| K7 | 문구 편집은 **이후 요청에만 적용**, 기존 건은 스냅샷 유지 |

## 12. 라이선스·티켓 규약 (Step 7 확정)

### 배치의 경계 — Q-21과의 정합성
**배치가 있는 것: 알림 발송(일 1회 09:00)** — 만료·결제일·연체·리마인드는 "특정 날짜에 사람에게 도달해야 하는 행위"이므로 본질적으로 스케줄이 필요.
**배치가 없는 것: 감가상각 산출** — 요청 시점에 계산하면 되는 값. Q-21 결정은 감가상각에만 적용된다.

### 라이선스 수량 정합성
- **보유 · 배정 · 잔여 3값을 항상 함께 표시.** 초과는 음수 + 경고색
- **총량 검증 + 구매내역별 검증 이중 확인** — 총량만 보면 어느 구매분의 초과인지 알 수 없음
- **미연결 배정을 명시 표시** — 초과의 실제 원인이며, 조용히 넘기면 영원히 발견되지 않음
- 초과는 **차단이 아니라 경고** — "선배정 후구매" 실무를 막으면 업무가 멈춤

### 렌탈 비용
- **귀속 월 ≠ 결제일.** 8월 사용분이 9월 1일 결제. 대시보드는 **귀속 월 기준** 집계
- 사용량 기반 계약(AWS 등)은 **예상액·실제액 분리**. 고정액 가정 금지
- 해지는 삭제 아님 — 상태 변경 + 지출 이력 보존

### 티켓 → 자산 자동등록
- **신규구매 티켓에만** 적용. 완료 처리 시 **티켓 상세 안에서 자산 등록 폼**이 열림
- 연쇄 처리: 자산 생성 → 요청자 배정 → 수령 확인서 요청을 **한 번에**
- 예상 금액이 아니라 **실제 취득가액** 입력 (감가상각 기준)
- 완료 후 티켓 수정 불가

## 13. 시각화 규약 (Step 8 확정)

**데이터의 일(job)이 형태를 결정한다.** 원본 기능정의서의 "원형차트"를 재검토해 다음과 같이 확정했다.

| 위젯 | 형태 | 원본 대비 |
|---|---|---|
| 자산 총계 4값 | KPI 스탯 타일 | 신설 |
| 종류별 / 위치별 현황 | **가로 막대 (값 내림차순)** | ⚠ 원형차트 → 가로막대 |
| 상태별 현황 | 단일 누적 막대 + 범례 | ⚠ 원형차트 → 누적막대 |
| 월별 비용 추이 | 누적 영역 (귀속월 기준, 12개월) | 선차트 → 누적영역 |
| 만료 예정 | **구간 카운트 + 표** | ⚠ 차트 → 표 |
| 전수조사 진행률 | 미터 | 신설 |
| 티켓 / 대여 / 라이선스 정합성 | KPI · 스탯 타일 | 신설 |

**원형차트를 쓰지 않는 이유** — 자산 종류 7개를 파이로 그리면 순위 비교가 불가능하다(사람은 부채꼴 면적을 비교하지 못한다). 만료 예정은 "무엇을 지금 처리해야 하는가"가 일이므로 차트가 아니라 표여야 한다.

| 키 | 규칙 |
|---|---|
| V1 | **단일 축** — 이중 축 차트 금지. 척도가 다르면 차트 2개 |
| V2 | 범주색은 고정 순서 배정, 순환 금지. **색은 순위가 아니라 대상을 따른다** |
| V3 | 계열 2개↑ 범례 필수, 4개 이하는 직접 라벨 병행 |
| V4 | 7범주 상한 — 초과 시 "기타"로 접거나 표로 전환 (색을 늘리지 않음) |
| V5 | 상태색(정상·경고·위험)은 **예약색**, 범주색으로 재사용 금지 |
| V6 | 차트 텍스트는 계열색이 아니라 잉크색 |
| V7 | 모든 차트에 호버 툴팁 기본 (모바일은 탭) |
| V8 | "표로 보기" 전환 제공 — 색 의존 경로 회피 |
| V9 | 라이트·다크 **각각 설계** (반전 아님) — 테마 적용 시점 과제 |
