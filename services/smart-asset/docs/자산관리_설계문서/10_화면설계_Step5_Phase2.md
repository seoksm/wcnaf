## §0 전제 — 전수조사의 역할

| 항목 | 내용 |
|---|---|
| **Q-29 확정** | 초기 자산 생성은 엑셀 양식 업로드 로 확정(양식 v1 제작 완료). 따라서 전수조사는 초기 데이터 구축 도구가 아니다. |
| **역할** | 이미 등록된 자산이 실제로 그 자리에 있는지, 상태가 대장과 일치하는지 확인한다. 회계 감사 대응과 분실 조기 발견이 목적. |
| **신규 등록** | “임직원 신규 자산 등록 허용”은 필수가 아닌 선택 옵션. 실사 중 미등록 자산이 발견되는 예외 상황을 위한 장치다. |

## §1 검수 상태 모델

대상 자산 하나하나가 아래 상태를 지난다. 이 흐름이 화면 3개(관리자 현황 · 임직원 참여 · 리포트)의 공통 기반이다.

**흐름**: 미확인 조사 시작 시 전 대상 → 확인 QR 스캔 + 사진 → 승인 검수자 확인 → 반려 → 미확인으로 복귀 → 이상 파손·위치불일치·타인보유

- **I1** — 대상 자산은 조사 시작 시점에 스냅샷으로 고정한다. 조사 중 자산이 새로 등록되거나 위치가 바뀌어도 대상 목록은 변하지 않는다. 이걸 실시간 조회로 만들면 “참여율이 어제보다 떨어졌다”는 현상이 생긴다.
- **I2** — 동일 임직원은 하나의 진행 중 조사에만 참여한다. unique(inventory_id, member_id) 제약 + 진행 중 조사 간 중복 대상 검사. 두 조사에 같은 자산이 걸리면 어느 쪽 결과가 진실인지 알 수 없다.
- **I3** — 확인은 QR 스캔으로만 인정한다. 목록에서 체크만 하는 방식은 실사가 아니라 서류 작업이 된다. 단 라벨이 없거나 훼손된 경우의 예외 경로를 둔다(§3 참조).
- **I4** — ‘이상’은 별도 상태다. 확인은 됐지만 대장과 다른 경우 — 파손, 위치 불일치, 타인 보유 — 를 ‘확인’에 섞으면 참여율 100%인데 문제가 묻힌다.
- **I5** — 반려하면 미확인으로 돌아간다. 사진이 흐리거나 다른 자산을 찍은 경우 검수자가 반려하고, 임직원에게 재검수 알림이 간다.
- **I6** — 조사 종료 후 상태는 변경할 수 없다. 종료된 조사는 append-only 기록물이며, 잘못된 결과는 새 조사로 바로잡는다.

> ⚠️ 가장 어려운 설계 지점 — 조사가 끝났는데 미확인으로 남은 자산  
> 실사는 100%로 끝나지 않는다. 휴직자, 출장자, 라벨이 떨어진 자산, 창고 깊숙이 있는 자산이 반드시 남는다. 606건 중 20~30건은 정상적인 결과다.  
> 이걸 자동으로 분실 처리하면 재앙 이다 — 휴직자 노트북이 분실로 찍히고 자산총계가 틀어진다. 반대로 그냥 두면 실사의 의미가 없다 — 매 조사마다 미확인이 누적되고 아무도 책임지지 않는다.  
> 설계 답은 “미확인 자산 종결 처리” 화면(S-308)을 조사 종료 절차에 강제로 끼워넣는 것 이다. 관리자가 미확인 자산을 한 건씩 보면서 차기 이월 / 소재 확인(수기) / 분실 처리 중 하나를 반드시 선택해야 조사가 종료된다. 판단을 자동화하지 않고, 대신 판단하지 않고 넘어갈 수 없게 만든다.

### S-301 · 전수조사 생성 (임직원형)

**[도면 S-301] 전수조사 생성 — 임직원형**  ·  _패턴 P-3_

| 설계 포인트 | 내용 |
|---|---|
| **제외 임직원** | 원본 스키마에 없던 항목. 휴직·장기출장자를 미리 빼는 것이 미확인 자산을 줄이는 가장 값싼 방법 이다. 이걸 안 넣으면 종료 시 S-308에서 매번 같은 사람들을 처리한다. |
| **배정 형태 필터** | 임직원형은 개인배정 자산만 대상으로 두는 게 기본이다. 공용·미배정 자산은 임직원이 책임질 수 없으므로 관리자형(S-302)으로 돌린다. |
| **대상 미리보기** | 시행 전에 대상 자산 건수와 참여자 수를 확정 숫자로 보여준다. 시행 후 변경 불가이므로 이 숫자가 마지막 확인 지점이다. |
| **미매핑 경고** | Step 2 S-103의 미매핑 판정을 재사용. 안내가 안 가는 5명은 시작부터 미확인이 예정된 인원 이므로 시행 전에 해소를 유도한다. |
| **검수자 승인** | 옵션으로 둔다. 켜면 2단(확인→승인), 끄면 임직원 확인이 곧 확정. 소규모 조직은 끄는 편이 실용적이다. |

### S-303 · 진행 현황

**[도면 S-303] 진행 현황**  ·  _패턴 P-2 · 탭 3_

| 설계 포인트 | 내용 |
|---|---|
| **4개 지표** | 확인완료 / 승인대기 / 이상 / 미확인. “이상”과 “미확인”을 분리해 각각 색을 준다 — 이 둘이 조사의 실제 산출물이고, 확인완료 숫자만 크게 보여주면 문제가 묻힌다. |
| **미확인 분해** | 미확인 69건을 “미참여 11명 · 부분완료 8명”으로 사람 단위로 분해 해 보여준다. 자산 69건을 쫓는 것보다 사람 19명에게 연락하는 것이 실제 행동이다. |
| **선택 리마인드** | 자동 리마인드와 별도로 선택한 사람에게만 즉시 발송. 종료 임박 시 실제로 쓰는 기능이다. |
| **탭 3개** | 참여자별 / 자산별 / 이상보고. 기본은 참여자별 — 관리자의 행동 단위가 사람이기 때문이다. |
| **조사 종료** | 이 버튼을 누르면 바로 종료되지 않고 S-308(미확인 종결 처리)로 이동 한다. 미확인 0건이면 확인 팝업만 띄우고 종료. |

### S-308 · 미확인 자산 종결 처리

**[도면 S-308] 미확인 자산 종결 처리**  ·  _종료 필수 관문_

| 설계 포인트 | 내용 |
|---|---|
| **강제 관문** | 미처리가 1건이라도 있으면 종료 확정 버튼이 잠긴다. 관리자가 판단하지 않고 조사를 덮는 것을 구조적으로 막는다. |
| **장부가 노출** | 분실 처리는 곧 처분손실이다. 장부가를 목록에 띄워, 180만원 자산을 분실 처리하려는 순간을 관리자가 인지하게 한다. |
| **사유 자동 분류** | 미참여 / 휴직 / 라벨 훼손 / 소재 불명. 미참여와 휴직은 시스템이 자동 판정 (참여 이력·멤버 상태 기준)하고, 나머지는 관리자가 지정한다. 사유별 기본 처리 방법을 프리셋으로 제안한다. |
| **일괄** | 휴직자 자산 12건을 한 번에 “차기 이월”로 넘기는 것이 정상적인 운영이다. 단 분실 처리는 일괄에서 제외 한다 — 되돌리기 어려운 동작을 일괄로 열어두지 않는다(R6). |
| **이월 추적** | 차기 이월된 자산은 다음 조사 생성 시 “이월 대상 n건 포함” 안내 로 노출한다. 두 번 연속 이월되면 경고를 띄운다 — 영원히 이월되는 자산이 생기지 않게. |

**[도면 S-310 / S-311] 임직원 검수 흐름**  ·  _모바일웹 · HTTPS 필수_

| 설계 포인트 | 내용 |
|---|---|
| **연속 스캔** | 스캐너를 닫지 않고 연달아 읽는다. 외부 카메라 앱 → 링크 이동 방식이면 자산마다 앱을 전환해야 하는데, 웹 내장 스캐너는 같은 세션에서 이어진다. 이 시스템의 실질적 차별점이다. |
| **라벨 예외** | 규칙 I3의 예외 경로. 라벨이 없거나 훼손된 자산은 목록에서 직접 선택 하고 사진을 찍는다. 이 경우 검수 결과에 스캔 없이 확인 플래그가 남아 검수자 승인이 강제 된다. |
| **“제 자산이 아닙니다”** | 원본 설계에 없던 항목이지만 실사에서 반드시 나온다. 대장의 배정 정보와 실제 보유자가 다른 경우 다. 선택하면 이상 상태 타인보유 로 기록되고 관리자가 배정을 정정한다 — 실사가 잡아내야 하는 가장 값진 오류다. |
| **촬영 강제** | capture="environment" 로 앨범 선택을 차단한다. 일부 브라우저가 이 속성을 무시 하므로 촬영 시각과 업로드 시각을 함께 기록해 사후 판별 근거를 남긴다(Step 2 C-201 규약). |
| **완료 버튼** | 미확인이 남아 있으면 비활성 + 남은 건수 표기. 관리자가 “완료 버튼 노출”을 끄면 이 버튼 자체가 사라지고 관리자만 종결한다. |
| **HTTPS** | getUserMedia 는 HTTPS 전용이고 iOS Safari는 사용자 제스처 이후에만 카메라를 연다. “QR 검수 시작” 버튼 탭이 그 제스처 가 되도록 설계했다. |

> ℹ️ PoC 1순위는 여전히 이 화면이다. 저조도·곡면 라벨 인식률, iOS Safari 카메라 정책, 연속 스캔 중 세션 유지 — 이 셋을 실측하지 않으면 Phase 2 전체 일정이 흔들린다. Step 3에서 지목한 PoC 대상과 동일하다.

## §4 리포트 · 반복 시행

**[도면 S-305 / S-306] 리포트 · 반복 스케줄**

| 설계 포인트 | 내용 |
|---|---|
| **PDF 조건** | 종료 확정 후에만 PDF를 생성한다. 진행 중 리포트는 엑셀(참고용)로만. 감사 제출물이 미확정 상태로 나가는 것을 막는다. |
| **미확인 처리 섹션** | 리포트의 핵심 섹션 이다. “69건이 미확인이었고 그중 12건은 휴직자 이월, 2건은 분실 처리”가 기록되어야 감사에서 답할 수 있다. |
| **중복 방지** | 자동 시행은 직전 조사 종료를 전제 로 한다(규칙 I2). 진행 중 조사가 있으면 실행하지 않고 알림만 보낸다 — 조용히 건너뛰면 실사가 1회 누락된다. |
| **템플릿 복제** | 반기마다 대상 범위·옵션을 다시 고르는 건 낭비다. 직전 조사를 복제해 기간만 바꾸는 것이 기본 동선. |

| Q-34 | **라벨 없는 자산의 검수 인정** | 목록 직접 선택을 허용할지. 막으면 검수 자체가 불가능한 자산이 생긴다. | ① 허용 + 승인 강제 (권장) ② 전면 금지 (QR만) ③ 무조건 허용 |
| Q-35 | **조사 중 임직원 정보 수정 범위** | 넓게 열면 대장이 오염되고, 막으면 위치 오류를 못 고친다. | ① 위치·메모만 (권장) ② 수정 불가 ③ 사양까지 허용 |
| Q-36 | **“제 자산이 아닙니다” 신고를 받나** | 실사가 잡아낼 수 있는 가장 값진 오류 유형이다. | ① 이상 유형으로 수집 (권장) ② 메모로만 ③ 미제공 |
| Q-37 | **휴직·장기출장자 사전 제외** | 미확인 자산을 줄이는 가장 값싼 방법. 다만 멤버 상태에 휴직 값이 필요하다. | ① 제외 기능 + 휴직 상태 추가 (권장) ② 수동 개별 제외만 ③ 제외 없음 |

> ⚠️ Q-37은 스키마에 영향을 준다. Step 1에서 멤버 상태를 사용 / 정지 / 퇴사 3종으로 정했는데, 휴직자를 자동 제외하려면 휴직 상태가 하나 더 필요 하다. 4종으로 늘리는 것이 맞다 — 휴직을 정지로 처리하면 로그인이 막혀 복직 시 번거롭고, 사용으로 두면 실사 대상에 계속 잡힌다.
