## §1 프로세스 On/Off 파급 매트릭스

Step 1부터 “임직원 화면은 활성 프로세스의 함수”라고 말해왔다. 그 함수를 여기서 표로 확정한다. 이 표가 곧 화면 렌더링 조건 이며, 개발 시 조건 분기의 유일한 기준이 된다.

| 영향 지점 | 둘 다 OFF | 대여만 ON | 수령·반납만 ON | 둘 다 ON |
|---|---|---|---|---|
| 관리자 LNB | 자산 목록 · 전수조사 · 불용자산 | + 대여 현황 | + 확인서 현황 | + 대여 현황 · 확인서 현황 |
| 임직원 하단 탭 | 홈 · 내 자산 · 문의 (3탭) | + 대여 (4탭) | 홈 · 내 자산 · 문의 (3탭) | + 대여 (4탭) |
| 임직원 홈 카드 | 내 자산 수 · 전수조사 진행률 | + 대여 중 자산 | + 승인 대기 확인서 | + 대여 중 · 승인 대기 |
| assign_type 선택지 | 미배정 · 개인배정 · 공용 | + 대여가능 · 대여중 | 미배정 · 개인배정 · 공용 | + 대여가능 · 대여중 |
| 자산 상세 액션 | 수정 · 복제 · 배정 · 불용 | + 대여 이력 탭 | + 확인서 요청 · 확인서 탭 | 둘 다 |
| QR 스캔(S-217) 액션 | 조회 · 수리요청 | + 대여하기 / 반납하기 | 조회 · 수리요청 | + 대여 / 반납 |
| 알림 유형 | 13종 활성 | + 반납 연체 | + 확인서 요청 · 승인 완료 | 16종 전체 |
| 미승인 조회 차단 | 없음 | 없음 | 적용 — 미승인 자산 정보 비공개 | 적용 |
| 엑셀 양식 컬럼 | 배정형태에 대여값 제외 | 대여가능 포함 | 대여값 제외 | 대여가능 포함 |

- **C1** — 프로세스 설정은 캐시하고, 변경 시 즉시 무효화한다. 전 화면이 매 요청 참조하는 전역 상태이므로 DB 조회로 두면 안 된다(Step 1 S-002 설계).
- **C2** — 프로세스를 끌 때 기존 데이터는 지우지 않는다. 대여를 끄면 대여중 자산이 남아 있을 수 있다 — 진행 중 건이 있으면 끄기를 차단 하고 몇 건인지 알려준다.
- **C3** — 끈 프로세스의 과거 이력은 계속 조회 가능하다. 메뉴에서 사라져도 자산 상세의 대여 이력 탭은 데이터가 있으면 남긴다 — 감사 추적성이 설정으로 사라지면 안 된다.
- **C4** — 임직원 탭이 3개일 때와 4개일 때 레이아웃이 깨지지 않아야 한다. 탭바를 고정 4분할로 만들면 3탭에서 빈 칸이 생긴다. grid-template-columns: repeat(auto-fit, 1fr) 로 개수에 따라 균등 분할.

### 대여 상태 흐름

**흐름**: 대여가능 창고 대기 → 승인대기 승인 옵션 ON일 때만 → 대여중 QR 스캔 + 기한 설정 → 연체 기한 초과 시 자동 → 반납완료 QR 재스캔 + 상태확인

- **L1** — 대여 처리는 낙관적 잠금으로 동시성을 막는다. UPDATE... WHERE assign_type='대여가능' 의 영향 행 수가 0이면 “이미 다른 분이 대여했습니다”로 안내한다. 두 사람이 같은 자산을 동시에 스캔하는 일은 실제로 일어난다.
- **L2** — 연체는 상태가 아니라 파생값이다. loan 에 연체 플래그를 두지 않고 due_date < 오늘 AND returned_at IS NULL 로 판정한다. 배치로 상태를 갱신하면 그 배치가 실패한 날은 연체가 없는 것이 된다.
- **L3** — 반납은 원위치 반납 후 QR 재스캔. 반납 시 자산 상태 확인(정상/이상)을 강제 하고 이상이면 수리중 으로 전환 + 티켓 자동 생성 제안.
- **L4** — 연체 중이면 신규 대여를 차단한다 (설정 옵션). 차단 시 “반납하지 않은 자산 2건이 있습니다”로 무엇을 반납해야 하는지 함께 보여준다.
- **L5** — 대여 이력은 삭제하지 않는다. 자산이 불용 처리되어도 과거 대여 이력은 남는다(C3).

**[도면 S-410] 대여 현황**  ·  _패턴 P-1_

| 설계 포인트 | 내용 |
|---|---|
| **연체 강조** | 연체는 일수까지 표시 한다. “연체”만 표시하면 1일과 13일이 같아 보이고, 관리자가 우선순위를 못 정한다. |
| **D-day** | 기한 임박(D-1, D-day)도 별도 표기. 연체가 되기 전에 알려주는 것이 회수보다 싸다. |
| **연장 횟수** | 1/1 형태로 사용/한도 를 표시. 한도를 다 쓴 건은 연장 요청이 거절될 것을 관리자가 미리 안다. |
| **관리자 대행** | 임직원이 앱을 못 쓰는 상황(계정 미발급, 외부인 사용)이 있으므로 관리자가 대신 대여 처리 하는 경로(S-412)를 둔다. 대여자는 멤버 선택. |

**[도면 S-420 / S-421] 임직원 대여 (모바일웹)**  ·  _S-217 진입점 분기_

| 설계 포인트 | 내용 |
|---|---|
| **목록 → 스캔** | 대여 가능 목록에서 자산을 찾고, 실물 앞에서 QR을 찍어 대여 한다. 목록에서 바로 대여 버튼을 주지 않는 이유는 실물 앞에 있음을 QR로 증명 하게 하는 것이 대여 기록의 신뢰를 지키기 때문이다. |
| **기한 안내** | 대여 확정 전에 반납 기한과 연장 가능 횟수를 명시 한다. 나중에 “기한이 있는 줄 몰랐다”가 나오지 않게. |
| **대여중 표시** | 다른 사람이 대여 중인 자산도 목록에 남기고 대여자를 표시 한다. 숨기면 “창고에 있을 텐데 왜 목록에 없나”가 된다. |
| **연체 우선** | 내 대여자산에서 연체 건을 최상단에 경고 스타일로. 차단 사유도 그 자리에 적는다(L4). |
| **연장 신청** | 한도 내에서만 노출. 소진 시 버튼이 사라지고 “연장 한도를 모두 사용했습니다”로 대체한다. |

### 승인 흐름 — 전자서명을 승인으로 대체 (R5)

**흐름**: 요청 관리자 · 문구 스냅샷 고정 → 알림 메신저 · 미매핑자 이메일 → 임직원 승인 열람 → 동의 체크 → 승인 → 담당자 승인 반납만 · 2단 → 완료 append-only 보관

- **K1** — 요청 시점의 문서 본문 전문을 스냅샷으로 저장한다. 템플릿 ID만 저장하면 나중에 문구를 바꿨을 때 “그 사람이 무엇에 동의했는지”가 사라진다. 증빙 가치의 핵심.
- **K2** — 승인 증빙 4종을 기록한다 — 승인자 ID · 승인 일시 · 접속 IP · 승인 시점 자산 스냅샷. 서명 이미지 대신 이 넷이 근거가 된다.
- **K3** — 승인 레코드는 append-only. 수정·삭제 API를 만들지 않는다. 잘못된 요청은 취소(무효화) 레코드를 추가 하는 방식으로 처리한다.
- **K4** — 2단계 확인으로 고의성을 확보한다. 체크박스 동의 + 승인 버튼. 버튼 하나만 누르는 방식보다 “읽고 눌렀다”는 근거가 강하다.
- **K5** — 반납은 담당자 승인까지 완료되어야 최종 처리된다 (설정 옵션). 임직원이 반납했다고 주장하는 것과 담당자가 받았다고 확인하는 것은 다른 사실이다.
- **K6** — 미승인 자산은 정보 조회를 차단한다 (설정 옵션). 승인 전까지 임직원 화면에서 자산 상세가 열리지 않는다 — 승인을 강제하는 장치.

**[도면 S-431 / S-432] 확인서 현황 · 담당자 승인**  ·  _패턴 P-1 · P-2_

| 설계 포인트 | 내용 |
|---|---|
| **3상태** | 승인대기 / 담당자 승인대기 / 완료. 2단 승인이라 상태가 3개 다. 하나로 뭉치면 지금 누가 액션을 해야 하는지 모른다. |
| **좌우 분할** | 왼쪽에 스냅샷된 문서 본문, 오른쪽에 승인 증빙과 담당자 액션. 승인하는 사람이 문서와 근거를 동시에 봐야 한다. |
| **IP 마스킹** | 접속 IP는 증빙이지만 부분 마스킹해 표시하고, 전체 값은 감사 로그에서만 조회한다. |
| **반납 후 상태** | 담당자가 승인과 동시에 자산의 다음 상태를 지정 한다. 보관/미배정이 기본이고, 이상이 있으면 수리중으로. 이 한 화면에서 처리해야 자산이 붕 뜨지 않는다. |
| **재발송** | 기한이 임박·경과한 건은 재발송 액션을 목록에 노출. 리마인드 자동 발송과 별도로 개별 재촉이 필요하다. |

**[도면 S-440] 확인서 승인 (임직원 · 모바일웹)**  ·  _2단계 확인 · K4_

| 설계 포인트 | 내용 |
|---|---|
| **2단계** | 체크박스 동의 + 승인 버튼. 체크 없이는 버튼이 비활성. 클릭 한 번으로 끝나는 방식보다 “읽고 동의했다”는 근거가 강해진다(K4). |
| **본문 스크롤** | 문서는 모바일에서 자체 스크롤 영역 에 둔다. 페이지 전체가 길어지면 승인 버튼을 찾지 못한다. |
| **기록 고지** | 승인 버튼 아래 “승인자·일시·접속정보가 기록됩니다” 를 명시한다. 증빙 수집을 숨기지 않는 것이 나중에 분쟁에서 유리하다. |
| **차단 안내** | 미승인 상태에서 자산 상세를 열려 하면 차단 이유와 승인 링크 를 함께 보여준다. 그냥 막으면 고장으로 읽힌다. |
| **완료 후** | 승인 완료 알림이 가고, 홈의 “확인 필요” 카드가 사라진다. 문서는 내 자산 → 확인서 탭 에서 언제든 재열람. |

> ⚠️ S-433 확인서 문구 관리 — 스냅샷과의 관계를 명확히 해야 한다.  
> 문구를 편집하면 이후 요청에만 적용 된다. 이미 요청된 건은 스냅샷된 본문을 그대로 유지한다(K1). 화면에 이 문장을 반드시 적어두어야, 관리자가 “문구를 고쳤는데 왜 옛 문서에 반영이 안 되나”로 혼란하지 않는다.  
> 템플릿은 수령용·반납용 2종. 치환 변수는 자산명·자산코드·취득가액·지급일·담당자·대상자 정도로 제한하고, Step 2 S-101과 동일한 칩 클릭 삽입 + 미정의 변수 검출 방식을 재사용한다.
